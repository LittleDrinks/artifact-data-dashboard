# 特性：知识图谱节点高亮（KG Node Highlight）

**短名**: kg-node-highlight

## 概述

在图谱可视化中为若干“高亮节点”提供视觉突出展示：一旦某个或多个节点被标记为高亮，系统应将这些节点放大并以特殊荧光色标记，同时使未被高亮的其它节点灰度化并缩小，从而在视觉上突出展示查询/问答/搜索结果的核心实体。大模型智能问答与图谱搜索的输出应以高亮节点的形式呈现，用户可基于高亮节点进行交互（定位、展开、查看详情、继续探索）。

## 目标用户与动机

- 产品使用者：数据分析师、知识工程师、普通业务用户。
- 目的：快速识别并聚焦与查询/问答结果相关的重要实体，提升信息获取效率和可读性。

## 范围（Scope）

- 包含：
  - 在主图谱画布（单页/单视图）实现节点高亮视觉状态。
  - 支持多个同时高亮的节点。
  - 将大模型（LLM）问答结果与图谱搜索结果映射为高亮节点集合并在画布中呈现。
  - 支持用户通过点击/搜索结果点击触发高亮，支持取消高亮和清除全部高亮。
- 不包含：
  - 后端检索/问答算法的改动，仅前端可视化高亮与前端接收并显示的逻辑。
  - 多视图/跨窗口的同步高亮（除非另行明确）。

## 用户场景与测试（必须可测试）

- 场景 A — 单节点问答展示：用户向大模型提问，模型返回实体 A；前端将实体 A 在图谱上高亮并居中显示。测试：当模型结果包含实体 A 的 id，点击“查看结果”后，画布上实体 A 显示为高亮状态且可见。

- 场景 B — 多节点聚合高亮：图谱搜索返回实体集合 {A, B, C}；系统同时高亮这三节点。测试：三节点都呈现高亮视觉；其余节点灰度并缩小。

- 场景 C — 交互操作：用户点击某一高亮节点，节点进入“聚焦”模式（更明显的放大/边框），侧栏显示详情；再次点击或点击空白处取消该节点高亮。测试：点击行为能切换聚焦并触发详情面板显示/隐藏。

- 场景 D — 高亮冲突与增量：用户在已有高亮集合上再选一个节点，系统应允许叠加（多个高亮），并保持所有高亮节点一致的高亮样式。测试：依次选中 4 个节点后，画布显示 4 个高亮节点，其余节点为灰度小图标。

## 功能性需求（可测试、无模糊）

1. 高亮状态的视觉规则
   - R1.1：被高亮的节点应放大到默认大小的 1.4×（可配置），并应用荧光风格（默认荧光色示例：亮黄色/荧光绿）。
   - R1.2：被高亮的节点边缘可选用发光或粗边框以增强可视感。
   - R1.3：非高亮节点应灰度化并缩小为默认大小的 0.6×（可配置），点击仍然可交互（响应点击/悬停）。

2. 多高亮支持
   - R2.1：最多支持同时显示 N 个高亮节点（N 的合理上限可配置，默认无限制；如出现性能问题再调整）。
   - R2.2：当高亮节点数量增多，视图应自动调整缩放/平移以保证所有高亮节点可见（若适用）。

3. 触发与清除
   - R3.1：支持以下高亮触发源：用户点击画布节点、从搜索/问答结果点击条目、通过 API（前端调用）设置高亮集合。
   - R3.2：提供清除单个高亮和清除全部高亮的操作（UI 按钮或 API）。

4. 可访问性与可视化设置
   - R4.1：提供高亮与灰度的主题/颜色切换或配置以满足弱视/色盲用户（例如：提供形状/图标口径替代颜色表达）。
   - R4.2：在禁用动画或降低运动的辅助设置下，放大/缩小应为瞬时切换，不依赖动画。

5. 与问答/搜索集成
   - R5.1：当大模型问答返回若干相关实体 id 时，前端应能接收该集合并将其设置为当前高亮集合；若集合为空则提示“未找到匹配实体”。
   - R5.2：当图谱搜索返回结果时，支持将搜索结果映射为高亮集合并在画布中显示，且在侧栏或结果列表中高亮对应条目。

## 成功准则（可验证、无实现细节）

- S1（功能性）：对于 95% 的普通查询（结果集合 ≤ 20），用户在 0.2 秒内看到高亮结果并能识别主次节点（可感知延迟 ≤ 200ms）。
- S2（准确性）：当系统接收到包含实体 ID 的问答/搜索结果，画布上高亮集合与结果集合的一致率为 100%。
- S3（可用性）：在用户测试（10 名不同背景用户）中，至少 90% 的受测者能够在 5 秒内识别并点击高亮节点以查看详情。
- S4（交互）：清除全部高亮后，图谱恢复为默认视觉状态且所有节点恢复正常交互。

## 关键实体与数据模型（高层）

- 节点（Node）：具有唯一 id、显示标签、可视位置、当前视觉状态（default / highlighted / focused / disabled）等属性。
- 高亮集合（HighlightSet）：一组 Node id，前端用该集合驱动视觉呈现。
- 高亮触发事件（HighlightEvent）：来源（user-click/search/llm-api）、时间戳、payload（节点 id 列表）。

## 假设（Assumptions）

- A1：前端使用单一画布视图展示图谱（不是多窗口同步）。
- A2：后端/LLM 返回的实体包含可与图谱节点 id 映射的唯一标识符；前端负责映射和展示。
- A3：视觉样式（具体颜色、放大倍数）可在 UI 主题中配置，但规范中给出推荐默认值。

## 依赖

- 前端图谱渲染组件（负责节点渲染、缩放与交互）。
- 前端与后端/问答模块的通信接口（用于接收 LLM 或搜索返回的实体集合）。

## 验收准则（Acceptance tests）

- AT1：向前端触发包含单个实体 id 的问答结果，画布在 0.2 秒内高亮该实体（视觉放大并标记），测试通过。
- AT2：向前端触发包含 3 个实体 id 的搜索结果，画布同时高亮 3 个节点，且其他节点为灰度小尺寸，测试通过。
- AT3：手动点击某一高亮节点，应触发聚焦并打开侧栏详情；再次点击关闭，测试通过。

## 风险与回退

- RISK1：大量高亮节点可能导致渲染性能下降。回退：限制同时高亮节点数或降级视觉效果（不启用发光）。

## 高亮外观偏好（已选）

默认视觉风格：采用荧光黄色填充并带发光外边以增强可视吸引力（推荐色：#FFEA00，或按主题变量设置），同时提供颜色/图标替代以支持色盲与弱视用户（例如：在设置中可切换为“图标+粗边框”模式）。

说明：此默认样式可确保在大多数场景下迅速识别高亮节点；可通过设置调整为低侵入性样式（粗边框 + 半透明填充）或图标增强模式以改善可访问性。

## 高亮持久性与跨视图行为（已选）

默认行为：高亮在页面刷新/导航后不自动保留（不持久化），以避免在不同会话中造成混淆。为方便短期跟踪，提供显式的手动清除与保存操作：

- UI 提供“清除全部高亮”按钮以立即移除当前高亮集合。
- 可选功能：在设置中允许用户手动“保存当前高亮”（本地会话/浏览器存储），以便短期重访时恢复；持久化跨会话或跨设备需额外后端支持（另行评估）。

## 高亮性能上限与默认并发上限（已选）

默认策略：设置默认最大同时高亮节点数为 20（可配置），以在大多数使用场景中平衡可视效果与渲染性能。超过该数量时，按相关度/优先级只显示前 N 个高亮节点，并在结果列表中提示用户有更多匹配项且提供“显示全部/分批显示”选项。

说明：该默认上限可在配置中调整，或在检测到低性能场景时动态降低。

## 附录：实现建议（仅参考，不作实现约束）

- 提供前端接口 `setHighlight(ids: string[], source: string)` 与 `clearHighlights()`，供搜索/问答模块调用；内部维护 `HighlightSet` 并触发视图更新与焦点调节。
