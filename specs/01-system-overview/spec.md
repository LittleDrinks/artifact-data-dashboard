# 系统概述 - 需求规格

## 项目定位

**文物大数据与人工智能集成系统**（Artifact Data Dashboard）是一个面向博物馆、文物保护单位的**文物数字化管理与智能分析平台**。

**核心价值主张**：
- 对博物馆：统一的文物档案管理 + 知识图谱探索 + 自然语言检索
- 对文物保护单位：可选的修复记录管理 + 图像修复工具
- 对研究员：基于实证的文物知识问答（图谱数据支撑通用知识）

---

## 核心问题域

### 需要解决的业务问题

| 问题 | 用户痛点 | 预期解决方案 |
|------|----------|--------------|
| 文物信息分散 | Excel、纸质档案混存 | 统一的数据录入界面 + MySQL 集中存储 |
| 关系难以发现 | 文物-人物-地点关联靠记忆 | Neo4j 知识图谱可视化（本体视图） |
| 检索门槛高 | 非技术人员不会写 SQL/Cypher | AI 自然语言问答（可选是否使用图谱） |
| 破损图像修复 | 传统修复成本高、不可逆 | AI 图像修复（Inpainting）保存前后对比 |
| 修复过程记录 | 修复过程纸质记录易丢失 | 数字化的修复记录管理（可选插件） |

### 目标用户与场景

#### 1. 博物馆管理人员（主要用户）
- **场景**：日常藏品管理、展览筹备
- **需求**：
  - 文物基础信息录入（名称、年代、类别、尺寸、材质、收藏地）
  - Excel 批量导入导出
  - 知识图谱探索（发现文物关联）
  - AI 问答（"这批青铜器有哪些共同特征"）

#### 2. 文物保护修复人员（扩展用户）
- **场景**：文物修复项目管理
- **需求**：
  - 修复记录录入（损害类型、修复方法、材料、检测指标）
  - 图像修复（上传破损照片，AI 生成修复预览）
  - 修复前后对比展示
  - 保护修复知识图谱（查看某技术的适用案例）

#### 3. 研究员/策展人
- **场景**：学术研究、策展策划
- **需求**：
  - 基于图谱的关联分析（"某收藏家的藏品网络"）
  - AI 辅助知识获取（通过具体文物实例了解某类器物特征）

## 功能模块需求

### 核心模块（始终启用）

#### 1. 资产管理（Asset Management）

**功能需求**：
- 文物基础 CRUD（名称、年代、类别、尺寸、材质、收藏地）
- 支持自定义字段扩展
- 文件夹层级管理（无限嵌套）
- 多标签系统
- Excel 批量导入/导出（支持字段映射）

**非功能需求**：
- 列表页支持分页、排序、筛选
- 导入任务异步处理（大文件不阻塞）

#### 2. 知识图谱 - 本体视图（Knowledge Graph - Ontology View）

**实体类型**：
- **文物（Artifact）**：名称、年代、类别、尺寸、材质、收藏地
- **人物（Person）**：姓名、生卒年、身份（艺术家、收藏家、考古学家）
- **地点（Location）**：名称、类型（博物馆、遗址、收藏机构）
- **朝代（Dynasty）**：名称、起止年份
- **类别（Category）**：青铜器、陶瓷、书画等

**关系类型**：
- 文物 → 创作于 → 人物
- 文物 → 收藏于 → 地点
- 文物 → 属于 → 朝代
- 文物 → 属于 → 类别

**功能需求**：
- 力导向图可视化（D3.js）
- 实体搜索和联想
- 最短路径分析
- 关系追溯（点击边查看详情）

**非功能需求**：
- 单次渲染节点数 ≥ 200
- 支持缩放、拖拽、选中交互

#### 3. AI 智能问答（AI Chat）

**核心设计**：*通过图谱数据介绍通用知识*

**问答模式**（用户可在界面切换）：

| 模式 | 说明 | 示例 |
|------|------|------|
| **图谱模式** | 只查询知识图谱，回答基于实证的特定问题 | "哪些唐代青铜器收藏在故宫？" |
| **知识模式** | 基于图谱检索的实例，AI 归纳通用知识 | "唐代青铜器有什么特点？" → 先查图谱找实例，再总结 |
| **通用模式** | 不限制，AI 基于训练数据自由回答 | "青铜器制作工艺简介" |

**功能需求**：
- 自然语言问答
- 流式响应展示
- 多轮对话支持
- **用户可控配置**（在聊天界面）：
  - 切换 AI 模型（云端 / 本地 / 模拟）
  - 启用/禁用图谱 MCP（决定是否让 AI 调用图谱工具）
- 模式自动降级（云端 → 本地 → 模拟）

**非功能需求**：
- 首字响应时间 ≤ 3s
- 支持会话历史存储

---

### 扩展模块（插件化，可选启用）

#### 4. 文物保护修复（Conservation Plugin）

**适用用户**：文物保护单位

**扩展数据字段**（关联到文物）：
- 损害类型（裂纹、缺损、锈蚀、褪色等）
- 修复方法（清洗、补配、加固、上色等）
- 加固方法
- 检测技术（X射线、红外光谱等）
- 保护材料
- 检测指标

**知识图谱 - 保护修复视图**：
- 实体：损害类型、修复技术、材料、检测方法
- 关系：文物 → 存在损害 → 损害类型、文物 → 使用技术 → 修复技术

**功能需求**：
- 修复记录录入和管理
- 修复时间线展示

#### 5. 图像修复（Image Inpainting Plugin）

**工作流**：
1. 用户上传破损文物照片
2. 调用外部 API 进行 AI 修复
3. 显示修复前后对比
4. 保存结果（可选关联到修复记录）

**功能需求**：
- 图片上传（支持拖拽）
- 修复进度显示
- 前后对比滑块（Before/After Slider）
- 下载修复后图片

#### 6. 统计分析（Statistics Plugin）

**功能需求**：
- 词云分析（高频关键词）
- 年代分布图表
- 分类统计
- 数据增长趋势

## 技术约束

### 必选项
- **后端**：Node.js 16+（团队熟悉）
- **数据库**：MySQL 8 + Neo4j 4.4 + Redis 7.2
- **前端**：React 18 + Ant Design 5
- **AI**：Ollama（本地）/ DeepSeek（云端）
- **部署**：Docker Compose

### 插件系统约束
- 插件可独立启用/禁用
- 禁用插件时，其数据字段不在界面显示
- 禁用插件时，其图谱节点类型不参与查询

### 兼容性要求
- 支持 Chrome、Firefox、Edge 最新两个版本
- 响应式布局（最低 1280×768）

## 数据策略

### 当前阶段（v0.x）
- **聚焦核心**：只启用本体视图，完善 2485 条基础数据
- **暂不启用**：保护修复插件（数据缺失）

### 后续阶段（v0.8+）
- 逐步补充保护修复数据
- 启用保护修复插件
- 开放图像修复功能

## 术语表

| 术语 | 定义 |
|------|------|
| 文物 | 博物馆藏品，包括器物、书画、文献等 |
| 本体视图 | 关注文物本身属性的知识图谱（文物-人物-地点-朝代） |
| 保护修复视图 | 关注文物保护过程的知识图谱（损害-技术-材料） |
| 图谱模式 | AI 问答时只查询知识图谱，不自由发挥 |
| 知识模式 | AI 先查图谱获取实例，再归纳通用知识 |
| MCP | Model Context Protocol，AI 调用系统功能的协议 |
| Inpainting | 图像修复技术，填补图像缺损区域 |
