# 系统概述 - 需求规格

> **版本**: v2.0 - 工作台架构
> **更新日期**: 2026-02-15

---

## 项目定位

**文物大数据与人工智能集成系统**（Artifact Data Dashboard）是一个**工作台为中心的一站式文物研究平台**。

传统文物管理系统将功能分散在多个独立页面，用户需要频繁切换才能完成任务。本系统采用统一工作台架构，将文物探索、知识图谱、AI问答、图像修复整合为连贯的工作流。

### 核心理念

**不要让工具打断思考。研究人员应该在一个界面内完成从发现到分析的全部工作。**

## 核心价值主张

### 一键部署

```bash
# 5分钟启动完整系统
cp .env.example .env
docker-compose up -d
```

- 单个命令启动全部服务（前端、后端、数据库、AI）
- 零配置初始化，开箱即用
- 内置2485条示例文物数据，立即开始探索

### 功能集成

工作台界面将原本分散的功能整合为连贯体验：

| 传统方式 | 工作台方式 |
|----------|------------|
| 搜索页面 → 记录名称 → 切换图谱页面 → 查找节点 → 切换聊天页面 → 提问 | 搜索 → 点击结果 → 右侧自动显示AI关联分析 |
| 下载图片 → 打开修复工具 → 上传 → 修复 → 保存 → 返回系统上传 | 选中图片 → 右侧拖拽到修复面板 → 一键修复保存 |
| 记忆多个标签页状态，重复输入搜索条件 | URL自动记录完整状态，链接可直接分享 |

## 目标用户与场景

### 用户类型

| 用户角色 | 核心任务 | 工作台使用方式 |
|----------|----------|----------------|
| **博物馆管理人员** | 藏品研究、展览策划 | 左侧搜索浏览，右侧AI问答获取背景知识 |
| **文物保护修复人员** | 修复项目管理、技术参考 | 左侧查找文物，右侧图像修复+知识问答 |
| **研究员/策展人** | 学术研究、关联分析 | 左侧图谱探索，右侧AI归纳总结 |

### 典型工作场景

#### 场景一：研究员探索青铜器

**工作流程（全程在工作台完成）**：

1. **左侧搜索**：输入"商代青铜器"
2. **浏览结果**：点击"四羊方尊"查看详情
3. **自动触发**：右侧AI助手显示该文物背景信息
4. **探索关联**：切换到左侧图谱模式，查看四羊方尊的关联网络
5. **深度提问**：问AI"湖南宁乡还出土过哪些青铜器？"
6. **发现规律**：AI基于图谱数据归纳宁乡青铜器的共同特征

**价值**：从搜索到结论，无需离开工作台页面，思路不被打断。

#### 场景二：修复师修复破损文物

**工作流程（左右面板联动）**：

1. **左侧查找**：搜索待修复文物，选中进入详情
2. **右侧修复**：将破损照片拖拽到图像修复面板
3. **选择类型**：选择"去水印"修复类型
4. **查看结果**：修复完成后使用对比滑块查看效果
5. **保存记录**：一键保存修复结果到该文物的附件库
6. **知识补充**：问AI"这类裂纹通常采用什么加固材料？"

**价值**：文物信息与修复工具同屏呈现，参考资料触手可及。

## 功能模块需求

### 全局功能

#### 工作台布局管理

**需求描述**：
- 支持左右分栏布局，中间可拖拽分隔线调整宽度
- 面板宽度百分比持久化到URL参数，刷新不丢失
- 支持面板最小化/最大化切换
- 移动端自动切换为上下堆叠布局

**非功能需求**：
- 分隔线拖拽响应延迟 < 50ms
- 布局状态URL序列化后长度 < 500字符

#### 全局状态共享

**核心状态**：
```typescript
interface WorkbenchState {
  // 当前选中文物（左右面板共享）
  selectedArtifact: {
    id: string;
    name: string;
    metadata: ArtifactMetadata;
  } | null;
  
  // 当前选中图片（用于图像修复）
  selectedImage: {
    id: string;
    url: string;
    artifactId: string;
  } | null;
  
  // 上下文类型（决定右侧AI的行为）
  contextMode: 'artifact' | 'image' | 'general';
}
```

**联动规则**：
- 左侧点击搜索结果 → 自动更新 `selectedArtifact` → 右侧AI自动感知
- 左侧点击图谱节点 → 同上
- 右侧上传图片 → 更新 `selectedImage` → 关联到当前文物

### 左侧面板：文物探索

#### 模块 1：文物搜索 (Search Panel)

**功能需求**：
- **搜索框**：支持关键词全文检索（名称、描述、年代）
- **高级筛选**：按类别、朝代、材质、收藏地多条件组合
- **结果展示**：网格视图（图片+名称+年代）/ 列表视图（详细字段）
- **排序**：按相关性、年代、名称排序
- **选中交互**：点击结果项设为当前选中状态，触发全局联动

**与右侧联动**：
- 选中搜索结果时，右侧AI自动接收该文物上下文
- 可选：自动向AI发送问候消息"我正在查看'XXX'，请告诉我相关信息"

**非功能需求**：
- 搜索结果首屏加载时间 < 1s
- 支持虚拟列表，平滑滚动1000+结果
- 筛选器变更实时响应，无需点击确认

#### 模块 2：知识图谱可视化 (Graph Panel)

**实体类型**（本体视图）：
- **文物（Artifact）**：名称、年代、类别、尺寸、材质、收藏地
- **人物（Person）**：姓名、生卒年、身份（艺术家、收藏家、考古学家）
- **地点（Location）**：名称、类型（博物馆、遗址、收藏机构）
- **朝代（Dynasty）**：名称、起止年份
- **类别（Category）**：青铜器、陶瓷、书画等

**关系类型**：
- 文物 → 创作于 → 人物
- 文物 → 收藏于 → 地点
- 文物 → 属于 → 朝代
- 文物 → 属于 → 类别

**功能需求**：
- **力导向图可视化**：使用D3.js渲染，支持Canvas优化
- **交互操作**：
  - 缩放（滚轮/按钮）
  - 拖拽节点调整位置
  - 点击节点选中并显示详情浮层
  - 双击节点展开关联
- **布局模式**：力导向布局、环形布局、层次布局
- **选中联动**：点击图谱节点触发全局选中状态

**与右侧联动**：
- 选中图谱节点时，右侧AI自动接收该实体上下文
- 支持向AI提问图谱相关问题："这个收藏家的其他藏品有哪些？"

**非功能需求**：
- 单次渲染节点数 >= 200
- 力导向图布局收敛时间 < 3s
- 缩放流畅度 >= 30fps

#### 左侧面板模式切换

**支持模式**：
1. **搜索模式**：全幅显示搜索结果
2. **图谱模式**：全幅显示知识图谱
3. **分屏模式**：上半搜索列表，下半选中项关联图谱

### 右侧面板：智能助手

#### 模块 3：AI 智能问答 (Chat Panel)

**核心设计**：*通过图谱数据介绍通用知识*

**问答模式**（用户可在界面实时切换）：

| 模式 | 说明 | 示例 |
|------|------|------|
| **图谱模式** | 只查询知识图谱，回答基于实证的特定问题 | "哪些唐代青铜器收藏在故宫？" |
| **知识模式** | 基于图谱检索的实例，AI归纳通用知识 | "唐代青铜器有什么特点？" → 先查图谱找实例，再总结 |
| **通用模式** | 不限制，AI基于训练数据自由回答 | "青铜器制作工艺简介" |

**功能需求**：
- **模式选择器**：顶部下拉切换三种问答模式
- **MCP工具开关**：用户可启用/禁用图谱查询工具
- **对话界面**：
  - 消息历史（支持Markdown渲染、代码高亮、LaTeX公式）
  - 流式响应展示（Server-Sent Events）
  - 多轮对话支持
- **快捷问题**：预设常见问题按钮（"这件文物的年代？"、"有哪些相似文物？"）
- **智能上下文**：自动感知左侧选中的文物，回答时自动关联

**与左侧联动**：
- 接收左侧 `selectedArtifact` 作为对话上下文
- 可触发左侧图谱高亮特定节点（通过API指令）

**AI模式管理**：
- 自动降级机制：在线模式 → 本地模型 → 模拟模式
- 用户可手动锁定特定模式
- 状态变化实时通知（Toast消息）

**非功能需求**：
- 首字响应时间 <= 3s
- 流式响应间隔 <= 500ms
- 会话历史持久化存储

#### 模块 4：图像修复 (Inpaint Panel)

**工作流**：
1. 从左侧拖拽文物图片或本地上传
2. 选择修复类型（去水印、人脸修复、超分、上色）
3. 调用阿里云视觉智能API进行修复
4. 显示修复前后对比
5. 保存结果到当前文物的附件库

**功能需求**：
- **图片来源**：
  - 拖拽左侧搜索结果中的图片
  - 点击左侧文物详情中的图片"发送到修复"
  - 本地上传（支持拖拽）
- **修复类型选择**：下拉选择修复服务类型
- **预览对比**：
  - 左右并列对比
  - 前后对比滑块（Before/After Slider）
- **操作按钮**：修复、重新修复、保存、下载

**与左侧联动**：
- 修复完成后，可选"添加到当前文物附件"
- 修复后的图片可在左侧详情中查看

**非功能需求**：
- 修复进度实时显示
- 修复结果本地缓存，避免重复调用API
- 支持批量修复队列

#### 右侧面板模式切换

**支持模式**：
1. **问答模式**：全幅显示AI对话
2. **修复模式**：全幅显示图像修复
3. **分屏模式**：上半AI问答，下半图像修复

### 扩展模块（插件化，可选启用）

#### 模块 5：文物保护修复（Conservation Plugin）

**适用用户**：文物保护单位

**扩展数据字段**（关联到文物）：
- 损害类型（裂纹、缺损、锈蚀、褪色等）
- 修复方法（清洗、补配、加固、上色等）
- 加固方法
- 检测技术（X射线、红外光谱等）
- 保护材料
- 检测指标

**知识图谱 - 保护修复视图**：
- 实体：损害类型、修复技术、材料、检测方法
- 关系：文物 → 存在损害 → 损害类型、文物 → 使用技术 → 修复技术

**功能需求**：
- 修复记录录入和管理
- 修复时间线展示
- **当前状态**：数据缺失（0条），暂不启用

#### 模块 6：统计分析（Statistics Plugin）

**功能需求**：
- 词云分析（高频关键词）
- 年代分布图表
- 分类统计
- 数据增长趋势

**展示位置**：独立面板或工作台弹出层

## 技术约束

### 必选项
- **后端**：Node.js 16+（计划升级到20）
- **数据库**：MySQL 8 + Neo4j 4.4 + Redis 7.2
- **前端**：React 18 + Ant Design 5
- **可视化**：D3.js 7（知识图谱）
- **AI**：Ollama（本地）/ DeepSeek（云端）
- **部署**：Docker Compose

### 插件系统约束
- 插件可独立启用/禁用
- 禁用插件时，其数据字段不在界面显示
- 禁用插件时，其图谱节点类型不参与查询
- 禁用插件时，其右侧面板模式选项隐藏

### 兼容性要求
- 支持 Chrome、Firefox、Edge 最新两个版本
- 响应式布局（最低 1280×768）
- 移动端支持上下堆叠布局
