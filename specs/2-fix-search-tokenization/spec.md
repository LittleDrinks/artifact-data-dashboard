# 特性：改进搜索分词（Fix Search Tokenization）

**短名**: fix-search-tokenization

## 概述

当前系统在从用户自然语言问题中提取关键词时，分词结果包含无意义词（如“介绍”“一下”）或未正确拆分／标准化中文短语，导致搜索与图谱检索结果不准确或遗漏。例如：

- 问题："介绍一下彩绘釉陶人物俑"
- 目前提取：['一下彩绘釉陶人物俑']（或包含整个句子）
- 期望提取：['彩绘釉陶','人物俑'] 或 ['彩绘釉陶人物俑']（按语义拆分/标准化后）

目标是检查并修复关键词抽取（extractKeywords）与分词逻辑，提升分词准确率，支持：停用词过滤、中文分词与词组归一化、短语优先匹配，以及对问答/搜索场景的微调（例如保留疑问词用于意图识别，但不作为搜索关键词）。

## 目标用户与动机

- 产品使用者：研究人员、文物档案检索者、普通业务用户通过自然语言查询知识图谱与数据库。
- 目的：提高问答/搜索召回和精确度，减少错误匹配与空结果，提高 LLM + 图谱协同效果。

## 范围（Scope）

- 包含：
  - 修复 `extractKeywords` / 分词流程（主要在后端 `chat.routes.js` 或相应服务中）。
  - 在分词中添加中文停用词过滤（可配置）并对常用语句前缀（如“介绍一下”“请问”）做去除。
  - 使用已有的中文分词库（仓库中已含 `nodejieba`），并在必要时增加短语识别与合并规则（phrase merging）。
  - 单测覆盖主要行为（用一组示例句子验证抽取结果）。
- 不包含：
  - 重新设计全文检索引擎（仅调整查询端关键词提取与预处理）。
  - 前端 UI 改动（除非需要显示分词调试结果）。

## 用户场景与测试（必须可测试）

- 场景 A — 去除干扰词：
  - 输入："介绍一下彩绘釉陶人物俑"
  - 输出（期望）：`['彩绘釉陶人物俑']` 或 `['彩绘釉陶','人物俑']`
  - 测试：调用后端分词函数，断言返回的关键词数组不包含“介绍”“一下”等停用词。

- 场景 B — 短语合并：
  - 输入："彩绘釉陶 人物俑 的年代"
  - 输出（期望）：`['彩绘釉陶人物俑','年代']`（将相邻名词短语合并为语义单元）

- 场景 C — 保留意图词用于路由但不作为关键词：
  - 输入："这件文物是谁做的？"
  - 输出（期望关键词）：`['文物']`；额外返回 intent label 'who'（非关键词）

- 场景 D — LLM 问答场景：
  - 当 Chat 后端同时构建 graph query 与提供文本回答时，分词应既能提供搜索关键词，也能为 LLM 上下文构建辅助信息（如实体短语）。

## 功能性需求（可测试）

1. 分词流程
   - R1.1：实现中文分词步骤，优先使用 `nodejieba` 的精确模式或自定义词典。可配置启用/禁用。
  - R1.2：去除停用词（含常见礼貌用语、语气词、命令前缀）。疑问词（谁/什么/何时/哪里/如何 等）不作为停用词，而是单独抽取用于意图判定并放入 `intent` 字段；这些疑问词不会计入最终用于搜索的 `keywords` 集合。默认提供一套中文停用词表，且支持从配置加载自定义停用词。
   - R1.3：对常见短语（如文物类别名、专业术语）支持短语合并/优先匹配，可通过自定义词典扩展。

2. 意图分离
   - R2.1：在提取关键词外返回 intent（如 questionType: who/what/when/where/how），供路由逻辑/LLM 使用，但 intent 不计入搜索关键词集合。

3. 可配置与回退
   - R3.1：提供配置项以启用/禁用短语合并或调整停用词表。
   - R3.2：在分词失败或异常时，退化为简单的“按空格分词 + 标点拆分”以保证系统可用性。

4. 测试与监控
   - R4.1：新增单元测试覆盖 10+ 示例句（含中文复杂句、问句、短语、带停用词的句子）。
   - R4.2：在 Chat 路径中添加可选 debug 输出（仅在 DEBUG 模式），记录原始问题与提取到的关键词。

# 成功准则

- S1（准确率）：在一组 50 条混合样本（生产日志抽样 + 人工合成）的测试集中，关键词抽取的精确率与召回率均提升至少 20%（相对当前基线）。
- S2（稳定性）：分词错误导致的空查询/无结果场景减少 80%。
- S3（回退保障）：分词异常时能够优雅退化并返回可执行的关键词集合。

## 关键实体与数据模型

- KeywordExtractionResult: { keywords: string[], intent?: string, rawTokens?: string[], debug?: object }
- StopwordList: 可配置的字符串集合
- PhraseDictionary: 自定义短语集合，用于短语合并/优先匹配

## 假设

- A1：后端使用 Node.js，已安装 `nodejieba`（在 `package.json` 中可见）。
- A2：搜索/图谱查询基于关键词匹配（前端/后端会把 keywords 映射到 Cypher 查询或 MySQL 搜索）。

## 依赖

- `nodejieba`（或其它同类中文分词库）
- 后端 Chat 路径中的 `extractKeywords` 实现位置（`backend/src/routes/chat.routes.js`）

## 运维与维护

- 词典维护：`backend/config/phrase-dict.txt` 与 `backend/config/stopwords.json` 的常规更新频率为每月一次；若监控到新日志样本中出现显著的新术语或分布变化（新增高频未识别短语），则可触发提前更新。

- 词典自动化更新：提供脚本 `scripts/update-phrase-dict.js`，用于定期或按需扫描 Chat/搜索日志，提取高频但未在字典中的短语并生成候选词条清单；候选项需人工审核后合并到 `backend/config/phrase-dict.txt`。该脚本可由 CI/定时任务触发或由运维手动运行。

## 验收准则（Acceptance tests）

- AT1：针对示例"介绍一下彩绘釉陶人物俑"，`extractKeywords` 返回不包含停用词且包含语义短语（见上文）。
- AT2：在 DEBUG 模式下，Chat 服务打印原始问题与分词结果用于人工核验。
- AT3：所有新增单元测试通过。

## 风险与回退

- 风险：自定义短语词典不完备导致误合并。回退：允许在配置中关闭短语合并。
