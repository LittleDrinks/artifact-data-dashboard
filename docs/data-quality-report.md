# 数据质量审查报告

**审查日期**: 2026-04-16
**审查范围**: artifacts_list.json、artifacts_detail/、benchmark_qa.json、后端数据模型
**总体评分**: **B**

---

## 总体评价

数据集整体质量良好，818 条文物数据覆盖了禁止出境展览文物、青铜器、陶瓷、货币、石窟等多个类别。Benchmark QA 数据量充足（1572 条），答案经自动验证准确率高。主要问题集中在：非文物条目混入（5.6%）、知识抽取覆盖率偏低（关键字段 23%~47%）、数据-模型字段不匹配（6 个字段缺失模型映射）。

### 2.4 抽取覆盖率分析

- **高覆盖率字段**（summary/full_text ~73%）：约 27% 的条目缺少全文，原因包括：Wikipedia 页面本身内容为列表/索引页、非文物条目无描述文本、爬取失败
- **中覆盖率字段**（era ~47.5%）：原因包括：部分 Wikipedia 页面无 infobox、石窟类文物的时代字段在 infobox 中命名不同（如"登录年份"被误识别为 era）
- **低覆盖率字段**（material/museum/dimensions 23-31%）：许多 Wikipedia 页面的 infobox 中确实没有这些字段；另外 59 条条目关键结构化字段全部为空但含有文本

### 2.5 抽取准确性（20 条随机抽样）

| 抽检维度 | 结果 |
|----------|------|
| era 抽取准确性 | 已验证，与 infobox 一致 |

| location 抽取准确性 | 已验证，与 infobox 一致 |

### 2.6 已发现的抽取问题

#### P2：Era 值不一致

| 值 A | 值 B | 实际含义 |
|-------|-------|----------|
| 唐 (38 条) | 唐朝 (6 条) | 同一朝代 |
| 宋 (21 条) | 北宋 (13 条) | 含义不同但应统一格式 |
| 战国 (10 条) | 战国时期 (数据中) | 同一时期 |
| 西汉 (17 条) | — | 与"汉朝"语义重叠 |

需要标准化为统一格式。

#### P2：Museum 值不一致

| 值 | 条目数 | 问题 |
|-----|--------|------|
| 故宫博物院 | 19 | — |
| 北京故宫博物院 | 6 | 与"故宫博物院"重复 |
| 台北市士林区国立故宫博物院 | 28 | 包含区级行政信息 |
| 于上海博物馆 | 6 | 多余的"于"前缀 |
| 湖南省博物馆 | 9 | — |
| 湖南博物院 | 6 | 同一机构不同名称 |

#### P2：Material 值不规范

部分 material 字段为描述性句子而非标准材质名：
- "鼓不但可用于音乐性质" → 应为空或具体材质
- "大玉戈是商前期的玉质" → 应为 "玉"
- "文信圜钱采用石质" → 应为 "石"
- "永安五铢为青铜材质" → 应为 "青铜"
- "大明通宝材质" → 非材质值

#### P2：Missed Extractions（漏抽取）

仅发现 4 处信息框有数据但字段为空的情况：
- museum 漏抽取 3 条（误将"馆藏规模"字段识别）
- location 漏抽取 1 条

总体漏抽取率极低，抽取脚本质量良好。

### 2.7 完全空白的详情文件（42 条）

这些条目的所有关键字段（era, material, location, museum, dimensions, summary, full_text）均为空。原因分析：
- 部分为朝代/地区条目（如 三国、唐朝、商朝）
- 部分 Wikipedia 页面结构特殊（如列表页）
- 部分爬取可能失败

## 4. 数据与模型兼容性

### 4.1 字段映射分析

#### 模型字段 → 数据源映射

| 模型字段 | 数据源 | 兼容性 |
|----------|--------|--------|
| id | DB 自增 | OK |
| name | artifacts_list.name | OK |
| description | 无直接映射 | 缺失 — 可用 summary 或 full_text 填充 |
| category | artifacts_list.category | OK |
| era | artifacts_detail.era | OK |
| location | artifacts_detail.location | OK |
| image_url | 无数据 | 缺失 |
| tags | 无数据 | 缺失 |
| created_at | DB 默认 | OK |
| updated_at | DB 默认 | OK |

#### 数据中有但模型中无的字段

| 数据字段 | 存在位置 | 建议 |
|----------|----------|------|
| material | artifacts_detail | **建议添加到模型**（高价值，31% 覆盖） |
| museum | artifacts_detail | **建议添加到模型**（高价值，31% 覆盖） |
| dimensions | artifacts_detail | 可选添加（23% 覆盖） |
| summary | artifacts_detail | **建议映射到 description** |
| full_text | artifacts_detail | 可选存储 |
| infobox | artifacts_detail | 可选存储为 JSON |
| url | artifacts_list | 建议保留（来源追溯） |

### 4.2 字段长度兼容性

| 模型字段 | 模型限制 | 数据最大长度 | 是否溢出 |
|----------|----------|-------------|----------|
| name | 255 | 30 | OK |
| category | 50 | 10 | OK |
| era | 50 | 22 | OK |
| location | 100 | 32 | OK |

所有字段长度均在模型限制内，无需担心截断。

### 4.3 数据类型兼容性

- **tags 字段**：模型定义为 Text，当前无数据。若未来使用，建议统一为 JSON 数组格式（如 `["青铜器", "礼器"]`）而非逗号分隔字符串
- **description 字段**：模型定义为 Text，建议用 summary 填充（平均长度适中，无超长文本风险）

## 5. 问题汇总

### P0（阻塞性问题）

无。

### P1（重要问题）

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| 1 | 46 条非文物条目混入 | 影响搜索、统计、QA 质量 | 建立黑名单过滤或标注 `is_artifact=false` |
| 2 | 6 个数据字段无模型映射 | 导入时丢失 material/museum 等数据 | 扩展模型或在 description 中拼接 |
| 3 | 8 条文物缺少详情文件（繁体字问题） | 知识抽取不完整 | 统一文件名编码，补充爬取 |
| 4 | 26 条 QA 关于非文物条目 | 影响评估准确性 | 过滤或重新生成 |

### P2（改进建议）

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| 5 | Era 值不一致（"唐" vs "唐朝"） | 统计和筛选不准确 | 建立朝代标准化映射表 |

| 10 | tags 字段无数据 | 标签筛选功能不可用 | 从 category/material/era 自动生成 |

## 6. 改进建议优先级

1. **立即可做**：过滤 46 条非文物条目，清洗 material 值
2. **短期**：扩展后端模型（添加 material, museum, url 字段），建立 era/museum 标准化映射
3. **中期**：补充 image_url 数据，用 summary 填充 description，为 tags 自动生成标签
4. **长期**：从 full_text 中二次抽取遗漏的 era/museum/material 信息，提升覆盖率至 60%+
