# 文物大数据与人工智能集成系统 白皮书

## 项目概述

这是一个面向文博领域的人机协作集成工作台。我们把数据管理、知识图谱、AI分析这些原本分散在不同系统的功能，整合成一个统一平台。关键创新在于所有功能都封装成标准化接口（MCP），人类专家可以直接操作界面，AI助手也能调用同样的接口完成任务，两者协作过程完全透明可见。

## 背景与问题

传统文物数据管理存在三个割裂：

**数据孤岛**。文物信息散落在Excel、数据库、图片库、纸质档案里，研究员查一件文物的完整信息要在多个系统间跳转。

**人机割裂**。AI工具（比如ChatGPT）能回答问题，但没法直接操作业务系统；业务系统有数据，但AI进不来。研究员只能手动把数据复制到对话框里问AI，再把答案复制回来。

**流程不透明**。AI给出结论时，你不知道它查了什么数据、怎么推理的，出了问题无法追溯。

## 核心创新：MCP统一接口

MCP（Model Context Protocol）是Anthropic提出的一种开放协议，我们把它落地到文物领域。思路很简单：把每个功能（查数据、画图谱、修图片）都包装成一个标准服务，同时暴露给人类界面和AI调用。

举个例子：图像修复功能。人类用户可以在工作台上打开修复面板，上传图片、画遮罩、点击修复。同时，AI助手也能收到指令"修复这件青铜器的裂纹照片"，自动调用同样的修复接口。修复过程在界面上实时可见，人类随时介入调整。

这种架构的好处是：人类保留最终决策权，AI负责繁琐操作，两者共享同一个操作空间。

## 系统架构

系统分为四层：

**数据层**。SQLite存结构化数据（文物名称、年代、尺寸），Neo4j存关系数据（这件文物出土于哪里、属于哪个朝代、和谁是同款）。数据可以通过Excel批量导入，也可以让AI自动爬取网页抽取。

**服务层**。Python FastAPI统一后端，每个功能都是独立模块：数据查询服务、图谱可视化服务、AI对话服务、图像处理服务。服务之间通过内部API通信，也可以注册为MCP Tool供AI调用。

**接口层**。统一的后端路由，带JWT认证、限流保护、审计日志。OpenAPI文档自动生成。

**展示层**。React + TypeScript 前端，Stripe风格设计系统。左侧导航、中间主区域、右侧功能面板。所有面板都是MCP Tool的可视化形态。

## 当前功能

**数据管理**：文物数据的增删改查、关键词搜索、按年代/类别/地点筛选、Excel导入导出。

**知识图谱**：D3.js力导向图展示文物关系，支持节点拖拽、缩放、参数调节。涵盖文物、朝代、地点、材质、类别五类节点。

**AI对话**：支持多种大语言模型，SSE流式输出。thinking（AI推理过程）、tool_calling（工具调用及结果）、answer（最终回答）三阶段流式输出，用户能实时看到AI的完整思考链路。支持 LightRAG 语义检索和 Neo4j 图谱查询两种检索模式。

**数据大屏**：统计卡片、柱状图、饼图、词云，展示文物数据分布和系统使用情况。

## 答辩演示场景

**场景一：智能检索**。用户输入"商代青铜器上的饕餮纹有什么文化含义"，AI展示思考过程，调用知识库检索，右侧面板实时展示检索结果和来源，最终生成带引用的结构化回答。

**场景二：图谱探索**。点击"后母戊鼎"节点，展开关联关系——属于商代、出土于河南安阳、材质青铜、饰有饕餮纹，一目了然。

**场景三：数据概览**。Dashboard展示文物总数、朝代分布、类别占比、关键词云，快速掌握数据全貌。

## 技术亮点

- **Docker Compose一键启动**：FastAPI后端、Neo4j图数据库、React前端，全部容器化。
- **前后端实时通信**：AI对话用SSE流式传输，思考过程实时可见。
- **RAG+图谱双检索**：LightRAG 语义检索 + Neo4j 图谱查询，互补增强。
- **维基百科数据管线**：自动爬取→清洗→入库→构建图谱→生成QA基准，全流程自动化。
