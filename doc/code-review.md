# 搜索详情弹窗 Code Review 速记

## 本次重点发现
- 之前的 `resolveArtifactId` 会把 `slug`、`uuid` 等非数字字段当成 ID 去请求 `/api/artifacts/{id}`，一旦后台用数值型主键，这些请求必然 404，于是用户只看到“未找到更多详情”。现在只接受真正的数字候选值，并在缺少 ID 时直接提示用户，避免了伪错误。

## 已做的改动
- 把字段顺序、表格列配置、数据格式化抽到组件外部，减少每次渲染重复创建对象的开销，也方便以后复用/维护。
- 新增 `buildDetailRows` 和 `useMemo`，只在文物数据变化时重建表格行，逻辑更清晰。
- 统一弹窗内的告警状态，改用一个 `detailAlert` 对象保存类型和文案，渲染时更简洁，减少状态分支。
- 在缺少有效 ID 时不再发起网络请求，立即展示基础信息 + 温和提示。

## 后续可选优化
1. 在后端 `/api/artifacts/search` 返回中补充一个可靠的 `id` 字段映射规则（如果未来有视图/Union），让前端永远拿到主键。
2. 如果详情字段会越来越多，可以考虑给表格加上分类分组或折叠面板，避免用户在小窗口里长距离滚动。
3. 结合业务权限：若某些用户无权查看详情，可在 403 时给出更明确的提示，用同一套告警渲染逻辑即可。
